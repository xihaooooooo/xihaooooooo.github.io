redis过期策略，redis内存淘汰策略。
Redis 的过期删除采用 **惰性删除 + 定期删除**。访问 key 时会检查是否过期，这是惰性删除；同时 Redis 会周期性抽样检查带 TTL 的 key，并删除已经过期的 key，这是定期删除。
内存淘汰策略处理的是「内存达到 maxmemory 后空间不够怎么办」，可以选择 noeviction、LRU、LFU、random、TTL 等策略，并可以通过 allkeys 和 volatile 控制淘汰范围。

父子线程共享数据如何传递？
Java 普通线程之间的业务数据可以直接通过参数或者共享对象传递。
如果是 ThreadLocal 上下文，普通 ThreadLocal 不支持父子线程继承，InheritableThreadLocal 可以在线程创建时把父线程数据传给子线程。
但是在线程池里，线程是提前创建并重复利用的，所以 InheritableThreadLocal 会失效。
这种场景可以使用阿里的 TransmittableThreadLocal，也就是 TTL。它会在提交任务的时候 capture 当前线程上下文，执行任务之前 replay 到线程池线程，执行完成后再 restore，既实现上下文传播，也避免线程复用导致的数据污染。

.mybatis的底层原理？
MyBatis 本质上是对 JDBC 的封装。启动时它会解析 MyBatis 配置和 Mapper XML，将 SQL 封装成 MappedStatement 放到 Configuration 中。调用 Mapper 接口时，MyBatis 通过 JDK 动态代理生成 MapperProxy，根据接口全限定名和方法名找到对应的 MappedStatement，然后通过 SqlSession 调用 Executor。Executor 再通过 StatementHandler 创建 JDBC 的 PreparedStatement，ParameterHandler 负责参数绑定，最终通过 JDBC 执行 SQL。查询结果返回 ResultSet 后，由 ResultSetHandler 结合 TypeHandler、ResultMap 等机制映射成 Java 对象并返回。另外 Executor 层还涉及一级缓存，MyBatis 插件则可以通过拦截 Executor、StatementHandler 等核心组件扩展执行流程。
