分库分表是因为单库或者单表顶不住。其中分表是因为表中数据量太大会使B+树层高导致IO瓶颈，分库是因为连接数太多会使CPU内存IO的压力太大。
在这个项目上使用了水平分表，一共分了两个表，卷模板表，和用户表。卷模板表的分片键是shop_number然后用户表的分片键是user_id。分片数16和32
分表算法：
```
表下标 = abs(hashCode(分片键)) % 表分片数
```

ID是使用雪花算法算出来的，不能依靠自增

分库算法
```
库=hashCode(分片键)%表分片数/每个库的表数
```
查询的时候一定要带上分片键因为它是通过分片键来进行数据去哪个表或库的

不足：
如果改变表的数量和库的数量会有大量数据改变位置
因为它是按shop_number分的，所以如果一个特别火的商铺它的数据还是会在一个表里面
